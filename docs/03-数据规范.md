# AI赛事助手 · 数据规范（v6）

## 1. 数据来源与权威链

- 权威底表：飞书多维表格「AI赛事」表（人工维护）。
- 每日快照：`data/contests_YYYY-MM-DD.json`、`festivals/festivals_YYYY-MM-DD.json`。
- 站点只读快照构建，**不直接改网页数据**；结构改动必须先改底表。

## 2. 快照结构

```json
{
  "snapshot_date": "2026-10-13",
  "records": [
    {
      "record_id": "recxxxx",
      "名称": "2026金海豚奖·AI影像大赛（厦门国际动漫节）",
      "分级": "A",
      "截止日期": "2026-10-15",
      "征集状态": "开放征集中",
      "剩余天数": "2",
      "主办方": "厦门市人民政府主办，金海豚奖组委会承办",
      "官网": "https://…",
      "投递链接": "https://…",
      "报名费": "免费",
      "最高奖金": "总池约40–50万（AI短片金奖3万/AI漫剧金奖5万/黑客松…）",
      "命题": "自由投稿",
      "地区": "中国·厦门",
      "类别": "AI视频大赛",
      "赛事说明": "…",
      "计划备注": "…",
      "是否需要投递": "是",
      "是否已投": "否"
    }
  ]
}
```

## 3. 字段取值约定

| 字段 | 允许取值 | 禁止 |
|---|---|---|
| 分级 | `S` `A` `B` `C` | 空值、其他字母 |
| 征集状态 | `开放征集中` `待公布` `即将开放` `已截止` | 自由描述 |
| 截止日期 | `YYYY-MM-DD` 或空 | 相对时间、"待定"写在日期里 |
| 命题 | `命题` `自由投稿` 或空 | 其他文字 |
| 报名费 | 具体金额 / `免费` / `官方未公布` / `未核实` | 臆测金额 |
| 官网 | 主办方官方域名 | 聚合站（投奖、aitop100 等） |
| 投递链接 | 官方 submit > 官方 FF/Festhome > 邮箱 | 有官方入口时填聚合站 |

**多档截止取最后一档**；通知日、影展日不是截止日，不得写入。

## 4. 派生的核实状态

构建时按下表生成每条赛事的核实徽章：

| 值 | 含义 | 判定 |
|---|---|---|
| `ok` | 官网已核实 | 修正层里有 `verify.level = ok` |
| `fixed` | 已按官网更正 | `verify.level = fixed` |
| `warn` | 需要你再确认 | `verify.level = warn` |
| `none` | 未自动核实 | 无记录（通常是聚合站页面或需登录的页面） |

修正层文件 `scripts/overrides.json`：

```json
{ "records": { "recXXXX": { "fix": { "报名费": "€20–30" }, "verify": { "level": "fixed", "note": "原表写 $15–25，官网为 €30" } } } }
```
构建时先应用 `fix`（覆盖原字段），再写入 `verify`。上游数据更新后修正不会丢。

## 5. 质量校验（构建时执行，违反即中止或告警）

中止（不发布）：
- 记录数为 0
- 记录数比上一版减少超过 30%
- 超过 5% 的记录缺少 `名称` 或 `record_id`

告警（可发布，写入构建日志）：
- 截止日期格式不合规（自动置空）
- 分级不在枚举内（降为 C）
- 已过截止日但状态仍为征集中
- 官网/投递链接为空，或指向聚合站
- 报名费/最高奖金为空

## 6. 每天维护流程

1. 巡检信源，发现新赛事或变更。
2. 打开主办方官网逐字段核对（名称、主办方、截止、官网、投递、报名费、奖金、资格）。
3. 写底表；同步当日快照；重建站点。
4. 已过截止 7 天以上的条目移除；S/A 级移除前必须先确认官方是否延期。
5. 实质变更记入变更记录。


## 内部工作记录过滤（v6.1 新增）

底表「计划备注」「赛事说明」「报名费」里混有维护过程记录（采集渠道、核对流程、录入规则、聚合站名）。构建时按句过滤，用户看不到：

- 去掉 `【…】` 形式的工作日志标签。
- 含以下内容的句子整句删掉：来源 / 入库 / 收录 / 聚合 / 第三方 / 红线 / 用户澄清 / 表内 / 补录 / 清理 / 改为官方 / 维持 / 投奖 及聚合站域名。
- 报名费里的「第三方称/第三方数据」改写为「未经官方确认」；「投奖价」改写为「代投平台价」；括号里提到聚合站的说明换成「投递前请到官网确认」。
- 唯一投递入口是代投平台时保留链接（用户要用），但按钮文字显示「指定代投平台」，不显示平台名。
- 截止日必须是真实存在的日期（如 2026-02-30 会按待公布处理并告警），不再让构建崩溃。
- 在线读取失败自动重试 3 次，仍失败就中止，网站保持上一版。


## 派生字段（v7 新增）

| 字段 | 含义 | 规则 |
|---|---|---|
| `added` | 收录日 `YYYY-MM-DD` | 该 `record_id` 第一次出现在快照里的日期；最早一份快照里已有的为 `null`；同名换 ID 沿用原日期 |
| `changes` | 截止日调整 | `[{date, from, to}]`，`date` 是发现变化的快照日期；`from/to` 为 `null` 表示待公布；最多保留最近 3 条 |
| `trackedSince` | 比对起点 | 参与比对的最早快照日期，站点顶层字段 |
| `siteUrl` | 站点地址 | 环境变量 `SITE_URL`，未设置时用默认 GitHub Pages 地址；分享卡片与配文使用 |

历史快照读取失败只告警、不中止构建（只是少算上新）。RSS 按收录日倒序，`pubDate` 用收录日。


## v7 审查修订（对抗测试发现并修复）

1. **链接白名单（前后端双保险）**：构建时清掉非 `http(s)` / `mailto` 的链接并告警；页面渲染时再用 `safeUrl()` 过滤一遍，即便数据被直接改坏也不会生成 `javascript:` 链接。
2. **前端统一转义**：所有进入 HTML 的字段都走 `esc()`；注入 `<img onerror>` / `<script>` / 引号实测不执行（测试 `tests/e2e.cjs` 会生成一份"恶意数据站点"逐个页面验证）。
3. **日历导出符合 RFC 5545**：整行按 75 字节折行（含属性名，续行以空格开头），CRLF 换行，反斜杠 / 分号 / 逗号转义；实测 154 个事件零超长行。
4. **iCalendar 链接同样走白名单**，不再把 `javascript:` 写进 `URL:`。
5. **损坏的历史快照只告警**，不中断构建；不存在的日期（如 2026-02-30）按「截止待公布」处理。
6. `package.json` 去掉 `playwright-core`（CI 不装浏览器，避免安装失败导致部署中断）；浏览器测试改为可选，用 `npm i --no-save playwright-core` 手动跑。
