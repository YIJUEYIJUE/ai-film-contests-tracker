# AI 赛事信源收集 SOP（公众号 / 小红书 / 其他平台）

> 目的：把用户陆续发来的公众号文章、小红书笔记等链接，整理成"发布 AI 赛事信息的来源"收集库，
> **核心底线是"不出差"**——每个来源的身份必须精确锁定，按唯一编号（公众号 `gh_` 原始ID / 小红书 `userid`）锚定，物理上不会串到别的号。

---

## 0. 核心原则（不出差的底线）

1. **身份靠"原始 ID"锁定，绝不靠标题/名称去猜、去搜。**
   微信 = `gh_原始ID`（永不改、全局唯一）；小红书 = `userid`。这是每个号的"身份证"。
2. **四重核对**：写入前，名称 + 平台原始 ID + 头像 + 来源链接 必须互相印证，不一致不写。
3. **逐条回显给用户核对**：每条抓完贴出「名称 + 原始 ID + 链接」，让用户一眼确认是不是"那个号"。
4. **严格去重**：按「平台 + 原始 ID」判重；同号不同文章不新建，不同号绝不合并。
5. **缺失不编造**：抓不到的字段标"未获取"，绝不用假数据填坑。
6. **主页字段放各平台的真实账号主页**：小红书/官网用可外开的作者主页；微信无"可外开的网页主页"，用由 `biz` 生成的真实账号主页 `profile_ext?action=home&__biz={biz}`（普通浏览器打不开、需微信内，但它就是该号真实主页、且携带 `biz` 身份锚点，下游 AI/系统能据此锁定账号）。**微信文章链接只放进「代表内容」作可外开样本，绝不填主页字段。**

## 1. 各平台的身份锚点

| 平台 | 唯一锚点字段 | 主页链接形态 | 说明 |
|---|---|---|---|
| 微信公众号 | `gh_原始ID`（来自 `var user_name`） | 由 `biz` 生成的真实账号主页 `https://mp.weixin.qq.com/mp/profile_ext?action=home&__biz={biz}` | 微信无"可外开的网页主页"，`profile_ext` 是该号真实主页（需微信内打开，但携带 `biz` 身份、能锁定账号）；文章链接仅作代表内容 |
| 小红书 | `userid`（来自笔记页 `__INITIAL_STATE__`） | `xiaohongshu.com/user/profile/{userid}` | 作者主页可公开访问，能补简介/小红书号/IP属地 |
| 抖音 | `douyin_id` / `sec_uid`（作者页或分享链接解析） | 作者主页 `douyin.com/user/{sec_uid}` 或分享短链 `v.douyin.com/...` | 自动解析待接入；来链接时手工解析入库 |
| 即梦官网 | `uid` / 作者 ID（即梦创作页） | `jimeng.jianying.com/...` 对应作者空间 | 自动解析待接入；来链接时手工解析入库 |
| 官网类（通用，如 FilmFreeway官网） | `domain`（主域名，如 `filmfreeway.com`） | `https://{domain}`（须 `https://`） | 用域名作锚点，无需抓正文；Cloudflare 等风控站也能入库（手工构造候选即可） |

> ✅ **微信主页采用 `profile_ext?action=home&__biz={biz}`**（由抓到的 `biz` 生成）——它是该公众号的真实账号主页，且携带 `biz` 身份锚点，下游 AI/系统据此即可锁定账号；普通浏览器打不开、需微信内属正常（微信本无外开网页主页）。**文章链接只进「代表内容」，不填主页字段。**
> ⚠️ 搜狗微信检索入口是"搜索页"，可能串到同名号，**不作主链接**（仅作辅助检索）。
> ✅ 卡片同时显示 `gh_` 原始 ID，用户一眼能看出是不是那个号。

## 2. 微信公众号抓取要点（从文章链接 `mp.weixin.qq.com/s/xxx`）

请求头用移动端 UA + `Referer: https://weixin.qq.com/`，并对连续请求加 `sleep(3)` 间隔（防验证页，见 §9）。

从原始 HTML 提取（按优先级，命中即停）：

| 字段 | 提取正则（命中即停） |
|---|---|
| **公众号原始 ID（锚点）** | `var user_name\s*=\s*"([^"]+)"` → `gh_xxx` |
| 公众号名称 | `id="js_name"[^>]*>([^<]+)<` |
| biz（副锚点） | `var biz\s*=\s*"([^"]+)"` |
| 文章标题 | `<meta property="og:title"[^>]*content="([^"]*)"` |
| 公众号简介 | `signature:\s*'([^']*)'` 或 `var signature\s*=\s*"([^"]*)"` |
| 发布时间 | `var ct\s*=\s*"(\d+)"` → 时间戳转 `%Y-%m-%d` |
| 文章摘要 | `<meta property="og:description"[^>]*content="([^"]*)"` |
| 头像 | 见 §9（异步加载，需特殊处理） |

**homepage 取法（重要）**：主页字段必须放**公众号账号主页**，不是文章链接。微信无"可外开的网页主页"，故取由 `biz` 生成的真实账号主页 `https://mp.weixin.qq.com/mp/profile_ext?action=home&__biz={biz}`——它是该号的真实主页地址（普通浏览器打不开、需微信内，但数据上就是该号主页）。**文章链接只放进「代表内容」作可外开样本，绝不填入主页字段。**（`verify_consistency` 已强制：微信主页必须含 `__biz=` 账号标识，纯 `/s/` 文章链接会被判 critical 拦截。）

## 3. 小红书抓取要点（从笔记链接 `discovery/item/xxx`）

请求头用桌面端 UA。数据嵌在 `window.__INITIAL_STATE__`（先按 `</script>` 切出该段）。

**两步走**：
1. **笔记页** → 取 `userid`（作者 ID）、`nickname`、`avatar`（注意把 `\u002F` 还原为 `/`）、按 `note_id` 在 `__INITIAL_STATE__` 内定位**真实笔记标题**（排除页面壳子默认占位 `"想了解些什么？"`）。
2. **作者主页** `https://www.xiaohongshu.com/user/profile/{userid}` → 补 `redId`（小红书号）、`desc`（简介）、`ipLocation`（IP属地）。

| 字段 | 提取位置 |
|---|---|
| **userid（锚点）** | 笔记页 `__INITIAL_STATE__` 中 `"userid":"..."` |
| 昵称 | `"nickname":"..."` |
| 头像 | `"avatar":"..."`（还原 `\u002F`） |
| 简介 / 小红书号 / IP属地 | 作者主页 `__INITIAL_STATE__` 的 `"desc"` `"redId"` `"ipLocation"` |
| 代表笔记标题 | 笔记页 `__INITIAL_STATE__` 内按 note_id 定位的 `"title"`（排除占位） |

> ⚠️ **防串号硬规则（已写入代码）**：`userid` / `nickname` / `avatar` / `redId` / `desc` / `ipLocation` **一律只从当前笔记的「作者对象」提取**（路径 `note.{note_id}.user/author` 或 `note.{note_id}.noteCard.user/author`），**绝不从全文全局正则抓**。在全文里搜 `"userid"` 会命中评论区/他人 ID，导致把 A 号串成 B 号（名字/主页对不上）。作者对象取不到时，才用全文正则**兜底补充，且绝不覆盖已得字段**。

## 4. 防错机制清单（每条必做）

- [ ] **锚点唯一性**：该来源的原始 ID 是否已存在于收集表？存在→判重，不存在→新建。
- [ ] **四重印证**：名称 / 原始 ID / 头像 / 来源链接 彼此一致。
- [ ] **回显核对**：贴「名称 + 原始 ID + 链接」给用户确认。
- [ ] **去重规则**：同平台 + 同原始 ID → 跳过（哪怕来自不同文章/笔记）。
- [ ] **字段完整性**：头像、简介缺失时单独重试补抓，补不到标"未获取"。
- [ ] **链接外开**：小红书/官网主页转 `https://`、可外开；微信主页用 `profile_ext?__biz=`（携带身份，浏览器打不开属正常）。

### 4.1 代码层一致性闸门（程序自动兜底，§4 的强制执行版）

`scripts/tracker.py` 内置 `verify_consistency(rec)` + `is_critical(problems)`，在 **`ingest`（解析后、回显/写候选前）** 与 **`apply`（合并写库前）** 两处都会调用。命中以下任一关键问题即 `critical=True`，**整条禁止写入、不进库**：

- 缺平台（平台字段为空；注：抖音/即梦/官网等是**开放平台集合**，不会因"不是公众号/小红书"被拦，只校验自洽）
- 缺名称 / 缺身份锚点（`gh_id` / `userid` / `douyin_id` / `uid` / `sec_uid`）
- 微信主页不是 `https://mp.weixin.qq.com/mp/profile_ext?action=home&__biz=...`（须含 `__biz=` 账号标识）
- 小红书主页与 `userid` 拼接结果不一致
- 抖音/即梦/官网等主页非 `https://` 链接

效果：即便抓取逻辑偶发异常，任何"对不上"的记录都不会进库。已对"现有 11 条底表 + 3 类构造坏记录 + 2 类正常记录"验证通过（现有 11 条 0 问题，坏记录全部被拦，正常记录全部放行）。两个解析函数（`parse_wechat` / `parse_xiaohongshu`）也都会把 `homepage` 写入 `source`，供闸门校验。

## 5. 字段规范（收集表结构）

每条来源记录至少含：

```
platform        平台（微信公众号 / 小红书 / 抖音 / 即梦官网 / ...）
source.name     名称
source.platform 平台
source.gh_id    公众号原始ID（微信）   ← 锚点
source.userid   作者ID（小红书）        ← 锚点
source.domain   主域名（官网类，如 filmfreeway.com） ← 锚点
source.homepage 真实账号主页（微信=profile_ext?__biz=；小红书=作者主页）
source.avatar   头像 URL（https）
source.bio      简介
source.red_id / ip_location   （小红书附加）
representative_article / representative_note  代表内容（标题/链接/发布时间/摘要）
```

## 6. 去重规则

- 键 = `(platform, 锚点)`（公众号=`gh_id` / 小红书=`userid` / 官网类=`domain`）。
- 收到新链接 → 解析出原始 ID → 与收集表所有键比对：
  - 命中 → **跳过，不新建**（回复"重复 = idX"）。
  - 未命中 → 新建来源，id 自增。
- 不同号**绝不**合并（即使名称相似）。
- ⚠️ **数据模型**：来源是"**账号主体**"（公众号/官网/小红书/抖音/即梦等账号），**不是赛事/活动本身**。两个不同账号即便都发同一赛事，也是两条独立来源，不合并；只有同一账号（同平台+同锚点）才是重复。名称取账号名（公众号名称/官网名称）；主页取该账号真实主页——微信用 `profile_ext?action=home&__biz={biz}`，小红书/官网用作者主页（可外开）。

## 7. 主页链接规范（必须指向真实账号主页）

| 平台 | 采用 | 弃用 |
|---|---|---|
| 微信 | 真实账号主页 `profile_ext?action=home&__biz={biz}`（**另留可外开的文章链接作「备注」**） | 把文章 `/s/` 链接当主页（无法锁定账号身份）、搜狗搜索页（可能串） |
| 小红书 | 作者主页 `xiaohongshu.com/user/profile/{userid}` | — |
| 抖音/即梦/官网 | 作者主页 / 官网作者空间（须 `https://`） | 文章/笔记链接当主页 |

> 🛡️ **双保险（公众号专用）**：`profile_ext` 主页在普通浏览器打不开（需微信内），故对公众号**额外保留一条可外开的文章网页链接作为「备注」**（也可同时进「代表内容」）。主页用于锚定账号身份、`biz` 不串号；备注提供可点开的样本网页，两者并存、互不替代。下游/人工核查时：主页对不上 → 串号风险；主页打不开但备注能打开且账号一致 → 正常。

HTML 渲染时：所有 `http://` 头像/链接统一替换为 `https://`；`<img>` 加 `referrerpolicy="no-referrer"` 防防盗链裂图。

## 8. 收集库的使用与维护

- **用途**：本库是"发布 AI 赛事 / 电影节 / 征片 / 大赛信息的来源"清单，供之后查阅、检索这些号的发布内容。不做自动每日追踪，也不设追踪关键词。
- **新增信源**：收到新链接 → 解析身份锚点 → 按 `(平台, 原始ID)` 去重 → 逐条回显给用户核对 → 确认后入库并重渲染索引页。
- **平台是开放集合，但每条必须正确归类、绝不串台**：当前 `微信公众号`/`小红书`/`抖音`/`即梦官网`（用户后续还会陆续给其它赛事来源平台）。由 §4.1 一致性闸门强制校验——**不会因"不是公众号/小红书"而拒绝**，只校验"名称/锚点/主页是否自洽、是否串台"；无法从链接判断平台时交由用户指定，不自动乱标。
- **本地先完成，再同步飞书**：新来源先在本地底表完整入库 + 重渲染 HTML、确认无误后，再填飞书表 `tblSBncl1nJt3IE1`（保持两处一致）。飞书写入仍须先与用户确认。
- **索引页**：交付一个可视化网页（每个来源一张卡片，含头像/简介/主页链接/原始 ID/代表内容），可按平台筛选，既是汇总也是查阅入口。

## 9. 已知坑 & 解法（本次实战踩过）

| 现象 | 原因 | 解法 |
|---|---|---|
| 连续请求微信返回空数据/验证页 | 微信临时风控 | 请求间加 `sleep(3)`；单独重试该链接（带 Referer）即可恢复 |
| 微信文章页抓不到头像 | 移动/桌面版把头像交给 JS 异步加载（`hit_biz_headimg`），HTML 无内嵌 `headimg` 变量 | 搜 `wx.qlogo.cn/mmhead/.../132`，请求验证返回 `200 image/*` 后回填 |
| 小红书头像/链接含 `\u002F` | JSON 转义 | 还原为 `/` |
| 小红书代表标题是"想了解些什么？" | 命中有页面壳子默认占位 | 按 `note_id` 在 `__INITIAL_STATE__` 内定位真实标题，排除占位 |
| 用户误以为文章链接=公众号主页 | 微信文章页 vs 公众号主页是两回事 | 主页用 `profile_ext?__biz=` 真实账号主页（携带 biz 身份）；文章链接只进代表内容 |
| 微信主页浏览器打不开 | 微信本无外开网页主页，`profile_ext` 需微信内打开 | 属预期；`profile_ext?__biz=` 仍是正确的真实账号主页，下游靠 `biz` 锚定身份，不退回文章链接 |
